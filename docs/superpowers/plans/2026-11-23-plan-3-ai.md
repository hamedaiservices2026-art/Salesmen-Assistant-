# Plan 3: The AI Layer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rep records his day by a photo of the day-end report or a voice note and gets the same form he would have typed, pre-filled as a draft he reviews and confirms; he attaches photos to returns; he asks the assistant by text or voice about his own numbers, the month's incentives and the company's policy documents, and hears the answer read aloud. The admin switches AI on or off, edits how report labels map to fields, sees AI usage against the daily limits, and sees what reps ask most without seeing who asked.

**Architecture:** Same Next.js application. Everything that talks to a model lives under `src/server/ai` behind one provider interface (vision, speech-to-text, chat) with adapters for Gemini, Groq and OpenRouter and a deterministic fake used by every test and end-to-end run. A model reply is untrusted data: it is parsed with zod, mapped to known fields by pure functions in `src/domain/ai` and `src/domain/assistant`, and never saved or shown as money without passing those checks. Private photos go through a storage interface (`src/server/files`) with a local-disk adapter and a Supabase Storage adapter, and are served only by an authenticated route handler. No model takes part in any calculation: the assistant is handed figures the existing loaders already computed.

**Tech Stack:** as plans 1 and 2 (Node 22, pnpm 10, Next.js 16, TypeScript strict, Tailwind CSS 4, next-intl 4, Drizzle ORM 0.45, PGlite, `postgres`, zod 4, Vitest 5, lucide-react, exceljs), plus `sharp` (pinned exact with `pnpm add -E sharp`, added to `serverExternalPackages`) for decoding and re-encoding uploaded photos. Providers are called with plain `fetch`; no provider SDK is added.

**Spec:** `docs/superpowers/specs/2026-11-14-salesman-assistant-design.md` (sections 6–11, the AI services table in section 10, "Behavior at the edges"), product truth in `PRODUCT.md`. Mockups (structure and copy only; colours come from `src/ui/tokens.css`): `docs/design/day-close.mockup.html`, `docs/design/assistant.mockup.html`, the "what reps ask" card in `docs/design/admin.mockup.html`. Inputs carried from plan 2: `.superpowers/sdd/2026-11-16-plan-2-admin/rulings.md` (R1–R26) and `progress.md`.

**This is plan 3 of 4.** 20 tasks in 5 milestones. Not in this plan (plan 4): web push, install guide, service worker and offline queue, the supervisor's mobile team tab, the morning-brief cron. Hook points left for plan 4 are listed at the end.

## Decisions made

The owner has not ruled on these; each is the conservative choice and can be overturned (see "Open questions for the owner").

1. **AI is off for a new company until its admin turns it on**, after reading a notice about data use. The demo seed turns it on for `demo-co`.
2. **Each rep sees a one-time notice and must accept it before his first photo, voice note or question.** Declining leaves typing fully usable. Accepting again is required when the notice version changes.
3. **An AI draft is never stored as a close.** The extracted values live in the browser (form state, mirrored in `sessionStorage` for 24 hours so a reload does not lose them). The server keeps only a receipt row without values (`ai_drafts`), so a confirmed close can be stamped `photo` or `voice`. Reason: a stored draft close counts in the month totals (R22) and would be confused with upload-created drafts (R16).
4. **Voice recordings are not stored.** The audio is sent for transcription and discarded; only the transcript is returned to the rep's screen.
5. **Report photos are visible only to the rep who took them and are deleted after 30 days. Return photos are visible to the rep, his supervisor and the company admin, and are deleted after 180 days.** A photo not attached to a confirmed close is deleted after 24 hours.
6. **Photo size limit is 4 MB, not 8 MB:** Vercel refuses request bodies over 4.5 MB. The browser downscales to 1600 px on the long edge first (typically 300–600 KB).
7. **Conversations are stored on the server per rep, one rolling conversation, kept 30 days, and the rep can delete them at any time.** Admins and supervisors never see conversations.
8. **"What reps ask most" shows topics, not questions,** and only topics asked by at least 3 different reps in the last 30 days.
9. **Read-aloud uses the phone's own voices only.** When the phone has no voice for the rep's language the button is hidden. Server-generated speech (the spec's fallback) is not built in this plan.
10. **Daily limits** (requests): per rep 20 photos, 30 voice notes, 50 questions; per company 200, 300, 500; whole deployment 400, 600, 800. A failed request still counts.
11. **The assistant answers only from the rep's figures, his incentive notifications and the company's policy sections.** Customer-level questions (the mockup's "who has not bought?") are phase 2 and are not offered.
12. **Focus items are not read from a photo or voice note;** the rep types them. Returns are not read either.
13. **Model identifiers are configuration.** Defaults follow the spec (`gemini-4-hydrogen`, Groq `whisper-large-v3`); Task 1 verifies them against the providers' current documentation and corrects the defaults.

## Global Constraints

- Languages: `ar` (default, right-to-left), `en`, `ur` (right-to-left). Every user-visible string comes from `src/i18n/messages/*.json`; no hard-coded copy in components. Digits are always Western (`0-9`).

- The framework is newer than most references. When a Next.js, next-intl, Drizzle, or Tailwind API is uncertain, read the installed package's own docs or types under `node_modules` before guessing.
- Commit after every task with a message describing the change. Do not put model identifiers in commits or code.
- Lines with unit `outlets` store whole customer counts; coverage lines are not daily lines (`isDailyLine`).
- Every admin server function starts with `assertRole(ctx, [...])` and returns `{ ok: false, error: "not_found" }` for an id outside `ctx.companyId`; server actions never trust a role, company or user id sent by the browser. Admin pages call `requireRole(["admin"])`; rep pages and actions call `requireCtx()`.

- Each migration is generated with `pnpm db:generate --name <name>`; backfills are hand-written SQL in the same file.

Fix what differs before committing.

Added by plan 3:

- **No AI in any calculation.** A model never adds, multiplies, converts or rounds a figure the product stores or shows. Extraction returns each value as the text printed or spoken; `parseAmount` (and the spoken-number parser) turn it into an integer. The assistant states only numbers that are in the context it was given; a check in code enforces this.
- **A model reply is untrusted data.** It is parsed by a zod schema with `.strict()`, capped in length, and mapped to an allow-list of keys. Nothing from a reply is used as a database id, a URL, HTML, a file path or an instruction. Replies are rendered as React text nodes only.
- **Nothing read by AI is saved as confirmed without the rep pressing confirm.** No server path writes a close from a draft.
- **Provider keys** (`GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`) are read only in `src/server/ai/config.ts` and `src/server/files/store.ts`, held in a `Secret` wrapper, sent only in request headers, and never logged, returned to the browser, or included in an error. Provider response bodies are never logged.
- **The model has no tools.** No function calling, no browsing, no code execution is ever enabled in a request. It cannot change data.
- **What is sent to a provider:** the photo (re-encoded, metadata removed), the audio, the rep's question, his computed figures with labels, incentive and policy text. Never: PIN, login, phone, national id, the rep's name, the company's name, session tokens, other reps' data.
- **Provider base URLs are constants in code** (`https://generativelanguage.googleapis.com`, `https://api.groq.com`, `https://openrouter.ai`); the storage URL comes from `SUPABASE_URL` and must match `^https://[a-z0-9-]+\.supabase\.co$`. No URL is ever built from user input or from a model reply.
- **Tests and end-to-end runs never use the network.** They use the fake provider (`AI_PROVIDER=fake`) and the local file store. The live check `scripts/ai-smoke.mjs` is opt-in and is not part of any `pnpm` gate.
- **Limits (exact):** photo upload body 4 000 000 bytes; decoded photo at most 40 000 000 pixels; stored photo JPEG, long edge at most 1600 px; audio 3 000 000 bytes and 60 seconds; question 500 characters; answer 1500 characters; model reply 20 000 characters; context given to the model 60 000 characters; low-confidence threshold 0.80; draft and receipt lifetime 24 hours; conversation retention 30 days; usage log retention 90 days.
- **Migrations** continue from `0013`. New tables carry `company_id` and are filtered by it. Two documented exceptions read across companies: the deployment-wide daily counter (scope `global`) and the retention sweeps (system maintenance, bounded batches).
- New rep copy follows the tone of `ar.json` ("راجع الأرقام وعدّل لو فيه غلط"). Catalog parity (`src/i18n/catalog.test.ts`) must pass after every task.
- The build stays green after every task: `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm e2e`, `pnpm e2e:admin`.

## Review Focus

1. **A file id or draft id from another rep or another company** (photo URL, return photo attached to a close, draft receipt, notification id passed to "explain", conversation delete): answered as not found, nothing changes, no bytes served. Tests in Tasks 7, 8, 11, 16, 18.
2. **A model reply that is wrong, hostile or half-finished** (prose instead of JSON, an unknown line code, a negative or over-cap amount, a decimal on a cases line, a number the context does not contain, a link, text copied from a policy that says "ignore your instructions"): rejected or reduced to the valid part, never saved, never shown as a figure. Tests in Tasks 2, 9, 11, 13, 15, 16.
3. **Confirming a partly filled draft:** a field the photo or voice did not give stays empty and required, never 0; an admin-recorded line keeps the admin's amount; collections stay the sum of the collection lines (R17, R18). Tests in Tasks 9, 11, 14.
4. **Spending the free tier:** parallel requests cannot pass a limit, a failure counts, the kill switch and the company switch stop every provider call, and a signed-out or wrong-role request reaches no provider. Tests in Tasks 3, 5, 11, 16.
5. **A hostile upload** (SVG or HTML named `.jpg`, a 100-megapixel image, a file over the limit with a lying `Content-Length`, a path in a file name, EXIF with GPS): refused or cleaned; the stored bytes are always a JPEG the server encoded. Tests in Tasks 6, 7.
6. **Secrets and personal data in logs:** a provider error whose body repeats the key, a usage row, a thrown error: none contains a key, a question, a transcript or a photo. Tests in Tasks 2, 3, 4.

### Task 2: Provider interface, the fake provider and the runner (timeouts, retries, fallback, strict parsing)

**Files:**
- Create: `src/server/ai/types.ts`, `src/server/ai/run.ts`, `src/server/ai/json.ts`, `src/server/ai/fake.ts`, `src/server/ai/providers.ts`
- Test: `src/server/ai/run.test.ts`, `src/server/ai/json.test.ts`, `src/server/ai/fake.test.ts`

**Interfaces:**
- Consumes: Task 1 config.
- Produces (`types.ts`):

```ts
export type AudioMime = "audio/mp4" | "audio/webm" | "audio/ogg";
export type AiErrorCode = "timeout" | "rate_limited" | "provider_error" | "bad_request" | "invalid_output";
export class AiError extends Error { constructor(readonly code: AiErrorCode, readonly provider: ProviderName, readonly retryAfterMs?: number) }
// message is always `${provider}:${code}`; nothing from the provider's response is kept on the error.
export type Usage = { tokensIn: number | null; tokensOut: number | null };
export type TextResult = { text: string; usage: Usage };
export type VisionRequest = { image: Uint8Array; system: string; prompt: string; maxOutputTokens: number }; // image is always a JPEG the server encoded
export type SttRequest = { audio: Uint8Array; mime: AudioMime; language: Locale };
export type ChatRequest = { system: string; messages: { role: "user" | "assistant"; text: string }[]; maxOutputTokens: number };
export interface AiProvider {
  readonly name: ProviderName;
  modelFor(kind: AiKind): string | null;               // null: this provider does not do that job
  vision(req: VisionRequest, signal: AbortSignal): Promise<TextResult>;
  stt(req: SttRequest, signal: AbortSignal): Promise<TextResult>;
  chat(req: ChatRequest, signal: AbortSignal): Promise<TextResult>;
}
```

- `run.ts`:

```ts
export type RunOk<T> = { ok: true; value: T; provider: ProviderName; model: string; attempts: number; fallback: boolean; latencyMs: number; usage: Usage };
export type RunFail = { ok: false; code: AiErrorCode; provider: ProviderName | null; attempts: number; latencyMs: number };
export type RunDeps = { now: () => number; sleep: (ms: number) => Promise<void>; random: () => number };
export const CALL_TIMEOUT_MS = 12_000; export const DEADLINE_MS = 25_000; export const MAX_ATTEMPTS_PER_PROVIDER = 2;
export function runAi<T>(job: { kind: AiKind; providers: AiProvider[]; call: (p: AiProvider, signal: AbortSignal) => Promise<TextResult>; parse: (text: string) => T | null }, deps?: Partial<RunDeps>): Promise<RunOk<T> | RunFail>;
```

  Rules: providers are tried in order, skipping those whose `modelFor(kind)` is null. Each call gets an `AbortSignal` that fires at `min(CALL_TIMEOUT_MS, time left to DEADLINE_MS)`; an abort is `timeout`. `timeout`, `provider_error` and `rate_limited` are retried once on the same provider after `300 + random() * 600` ms (for `rate_limited`, `retryAfterMs` when given and ≤ 2000, otherwise no retry), only while the deadline leaves at least 2000 ms. `bad_request` and `invalid_output` (the reply is longer than 20 000 characters, or `parse` returns null) are not retried on the same provider; the next provider is tried. An error that is not an `AiError` is treated as `provider_error`. With no usable provider the result is `{ ok: false, code: "provider_error", provider: null, attempts: 0 }`. `fallback` is true when the provider that answered is not the first usable one. The function never throws and never logs.
- `json.ts`: `parseJsonReply(text: string): unknown | undefined` — accepts a reply that is exactly one JSON value, or exactly one fenced block (three backticks, optional `json`) holding one, with surrounding whitespace only; anything else, including JSON followed by prose, is `undefined`. Uses `JSON.parse` inside try/catch; refuses input over 20 000 characters before parsing.
- `fake.ts`: `fakeProvider(): AiProvider` implementing the fixtures in "Shared sample data"; `modelFor` returns `"fake-1"`; usage `{ tokensIn: null, tokensOut: null }`. It reads the image width with `sharp(...).metadata()`.
- `providers.ts`: `getProviders(kind: AiKind, config?: AiConfig): AiProvider[]` — `mode "off"` → `[]`; `"fake"` → `[fakeProvider()]`; `"live"` → the adapters of `providerOrder(kind)` that have a key and a model (adapters arrive in Task 4; until then `"live"` returns `[]`).

- [ ] **Step 1: Write failing tests** (scripted providers built in the test; `deps` with a fake clock, `sleep` recorded, `random: () => 0.5`):
  - first provider answers `{"a":1}` with `parse` accepting it → `attempts 1`, `fallback false`.
  - first provider throws `timeout` twice, second answers → `attempts 3`, `fallback true`, one sleep of `600` ms.
  - first provider throws `bad_request` → no sleep, second is called, `attempts 2`.
  - first provider returns `not json` (parse → null), second returns valid → `fallback true`; both invalid → `{ ok:false, code:"invalid_output", attempts 2 }`.
  - `rate_limited` with `retryAfterMs 1500` → one sleep of 1500; with `retryAfterMs 30000` → no retry, next provider.
  - a provider that never resolves: the signal aborts at 12 000 ms of fake time → `timeout`; with 24 500 ms already spent the retry is skipped.
  - a provider throwing `new Error("key=k-123")` → result `provider_error`; the returned object serialised with `JSON.stringify` does not contain `k-123`.
